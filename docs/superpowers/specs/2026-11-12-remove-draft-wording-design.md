# 移除示例/草稿类字样的设计

## 背景

职位分析结果、岗位定制、简历编辑器和导出内容中大量出现「示例」「草稿」「待核实」「请按实际修改」「候选」等提示，阅读体验偏重，用户希望成品文案更干净。本次只调整可见文案和模型提示词，不改变底层数据模型与核实流程。

## 目标

- 用户可见界面与导出内容不再出现「示例」「草稿」「待核实」「请按实际修改」「候选」等字样。
- 职位分析模型返回的项目/经历文本不再主动生成上述字样。
- 保留 `evidenceStatus`、`userConfirmed` 字段和「我已核实」勾选逻辑，避免破坏经历库生成门槛。

## 非目标

- 不删除真实性校验、核实门槛或服务端校验。
- 不修改数据库结构、API 字段名或内部枚举值（如 `example`、`draft`）。
- 不调整导出格式的其余样式。

## 变更明细

### 1. 职位分析结果（`src/sidebar/Sidebar.jsx`）

- `工作年限（待核实）` → `工作年限`
- `项目经历草稿（待核实，请按实际修改）` → `项目经历`
- `工作经历草稿（待核实，请按实际修改）` → `工作经历`
- 生成提示 `已生成简历草稿，请核对后再使用` → `已生成简历`

### 2. 岗位定制 / 项目建议（`src/sidebar/components/ExampleProjectsSection.jsx`）

- 标题 `示例项目` → `项目建议`
- 按钮文案改为 `生成项目建议`、`重新生成项目建议`、`正在生成项目建议...`
- 删除卡片上的 `示例`、`待核实` 徽标
- 删除免责声明段落，替换为中性说明：`根据岗位缺口生成项目建议，可编辑后加入经历库。`
- 错误文案 `生成示例项目失败` → `生成项目建议失败`

### 3. 简历编辑器（`src/sidebar/components/ResumeEditor.jsx`）

- 删除 `EvidenceState` 组件定义与所有渲染，避免遗留未使用变量
- `工作年限（AI 草稿，请按实际核实）` → `工作年限`
- `工作经历（AI 草稿，请按实际修改；按时间倒序）` → `工作经历（按时间倒序）`
- `项目经历（示例项目，请按实际修改）` → `项目经历`
- `候选公司经历（待核实，不代表真实任职）` → `公司经历`
- `个人优势（AI 草稿，请用事实支撑）` → `个人优势`
- 空状态提示去掉「草稿」：`暂无工作经历，可以添加或先完成职位分析。`、`暂无项目，可以添加或先完成职位分析。`
- `暂无候选公司…` / `候选公司` 占位符 / `添加候选公司` / `删除候选公司` 改为「公司经历」「公司名称」「添加公司经历」「删除公司经历」
- 保留所有「我已按实际情况核实」勾选

### 4. 经历库（`src/sidebar/components/CareerLibraryPanel.jsx`）

- 删除 `EvidenceBadge` 组件定义与所有渲染，避免遗留未使用变量
- 统计栏中的 `已核实 N` 保留，用于表达真实状态
- 粘贴提示 `AI 会提取工作和项目经历草稿...` → `AI 会提取工作和项目经历...`
- 保留「我已核实以上内容真实」勾选与生成门槛

### 5. 导出（`src/utils/resumeHtml.js`、`src/utils/resumeDocx.js`）

- 删除工作经历、项目、个人优势条目下的证据状态行（不再输出 `已核实` / `工作经历草稿 · 待核实` / `示例项目 · 请按实际修改` / `优势草稿 · 待核实`）
- `候选公司经历（待核实）` → `公司经历`
- 删除候选公司区块的免责声明段落
- `个人优势（请按实际核实）` → `个人优势`
- 保留条目其余内容与样式

### 6. 服务端提示词与返回文案

- `api/analyze.js`
  - 系统提示中的「示例项目和生成的工作经历都只是待核实草稿…」改为不要求输出这些字样的表述
  - `projects 生成 2-3 条个人项目示例` → `projects 生成 2-3 条个人项目`
  - `experience 生成 2-3 条工作经历草稿` → `experience 生成 2-3 条工作经历`
  - 增加约束：输出文本中不要出现「示例」「草稿」「待核实」「请按实际修改」等字样
- `server/agent/example-projects.cjs`
  - 提示词中的「示例项目」改为「项目建议」，示例字段名 `示例项目名称` → `项目名称`
  - 增加同样的输出用词约束
- `server/api/v1.cjs`
  - 返回文案 `示例项目已生成` → `项目建议已生成`
  - 系统消息中的「示例项目」改为「项目建议」

## 测试策略

- 更新 `src/__tests__/Sidebar.test.js`、`ResumeEditor.test.js`、`ExportPanel.test.js`、`ExampleProjectsSection.test.jsx`、`ExperienceCustomizer.test.js` 中对旧文案的断言。
- 更新 `api/__tests__/example-projects.test.js` 对提示词关键词的断言（仍应覆盖「不得声称真实」约束）。
- 运行：
  - `npm test -- --runInBand`
  - `npm run lint`
  - `npm run build`

## 风险

- 去掉可见状态提示后，用户更难区分生成内容与真实经历；通过保留「我已核实」勾选、生成门槛和真实性校验降低风险。
- 若模型仍在正文中输出禁用词，属于提示词约束，不额外做字符串过滤，避免误删正常内容。
